# Continuation authority

A Goal or project continuation stays bound to its confirmed project source,
task scope and budget. The original authorization stays attached to batch,
Manager decision and recovery evidence.

The execution snapshot records the project settings, Team configuration,
Skill bindings, selected model profiles and managed Provider settings.
Runtime changes produce a project conversation notice. New work uses the
current settings. Running processes keep their existing settings until they
finish. Provider fingerprints contain hashes, and notices contain no secrets.

A background Manager retry retains its original input and native thread when
the runtime can resume it. A context-window rejection displays the runtime
failure and retains the task and native session. A Goal paused for that reason
keeps its original work and evidence. The user can change to a model that
fits the retained context. Replaying a failed or uncertain attempt still
requires its original recovery evidence.

Project display labels, unrelated model profiles and formatting changes do
not produce execution-environment notices. Exact project identity, scope,
Stop, and delivery evidence continue through their existing controls.

## Verification

Local fixtures exercise continuation after Provider rotation and model
changes, the environment notice, preservation of a native thread across a
model change, and the context-window failure. The fixtures use synthetic
models and credentials.
