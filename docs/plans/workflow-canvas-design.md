## 1. 概念

画布是**视图画布（view canvas），不是编辑器**：用户不拖节点、不改拓扑；他们平移/缩放，
在三个语义层级间漫游，节点可点击展开细节。管线的水平条是画布在"总览层"的退化形态，
也是无障碍回退。

三个语义层级（semantic zoom，按缩放级别吸附）：

| 层级 | 缩放 | 内容 | 交互 |
| --- | --- | --- | --- |
| **L0 总览** | 0.5–0.8x | 整条 run：全部阶段 + 关卡（等价于现管线条，自动换行/分泳道） | 平移；点节点聚焦 |
| **L1 阶段** | 0.8–1.2x | 单个阶段放大：标题、状态、feedback、artifact 路径、证据徽章 | 点门卡 → 展开细节卡 |
| **L2 门卡细节** | 1.2–2x 或侧板 | 复用 Review 数据：推荐结论、证据摘要、决策动作（批准/修改/拒绝）、查看全文链接 | 决策动作直达（≤2 次交互到批准） |

## 2. 关键交互规则（防"为深挖牺牲日常"）

1. **批准路径 ≤2 次交互**：L0 点击 review-needed 节点 → L1/L2 细节卡直接带
   "批准/请求修改/拒绝"按钮（复用 `decide_approval` API，与 Review 同路径）。
   走查 3.0 必须实测这条路径的步骤数，超标则回退交互设计。
2. **平移**：拖拽空白处（非节点）、滚轮滚动画布、空格+拖拽；**缩放**：滚轮/捏合/
   工具条按钮（0.5–2x，按层级吸附）；双击节点聚焦到 L1；"适应视图"按钮回到 L0 全览。
3. **节点点击展开**：点击节点 → 画布内展开细节卡（不是跳页）；Esc 关闭回到上一级；
   再次点击收缩。展开态不改变布局拓扑（卡片浮层/侧板，而非重排节点）。
4. **键盘**：方向键在节点间移动焦点（焦点跟随视觉顺序），Enter 展开，Esc 收起/退出，
   +/- 缩放，F 适应视图。焦点环复用 `--product-focus` token。
5. **无障碍**：画布区域 `role="region"` + 说明；**管线条（v1 组件）保留为非画布回退**
   （JS 禁用或偏好简化时渲染管线条）；读屏用户在回退路径上完成全部任务。
   WCAG 2.2 AA（设计稿 §11）。
6. **状态不只靠颜色**：L0 图标 + 文本标签（复用 v1 状态矩阵），缩放层加深对比度。

## 3. 数据（零后端新增）

与管线 v1 完全同源：`build_workflow_steps`（status/action_label/feedback/artifact/
artifact_path/approval/number/title）+ `approval_reviews`（recommendation、
evidence_snapshot）+ `action_items`。并行分支（D3 未来）出现时：L0 画布按
`workflow_execution_plan_v2` 拓扑绘制分支与汇合点；数据未到位前保持顺序绘制。

## 4. 技术选型（待拍板）

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| **A. React Flow（@xyflow/react）**（推荐） | 成熟：缩放/平移/节点/边/小地图/键盘钩子；社区无障碍实践多 | 新依赖（~40KB gzip）；契约测试需调整 |
| B. 手写 transform（pan/zoom 自研） | 零依赖，完全可控 | 平移/缩放/焦点/吸附/键盘全自研，工期与 bug 面大 |
| C. 现有管线条 + CSS zoom | 最小改动 | 不是真画布，语义缩放/分支无解 |

约束：画布组件封装为 `WorkflowCanvas`，对外 API 稳定（props 同 `WorkflowPipeline` +
`levels`），契约测试只测组件 API 与回退路径，不测库内部；依赖锁版本。

## 5. 放置与页面关系

- **Work 页**：管线条位置升级为画布（L0 即管线条视觉，缩放进入 L1/L2）。
- **Review 页**：不变（画布门卡细节与 Review 共享数据与动作，Review 仍是深评审工作台）。
- **Home**：不引入画布；Home 保持 next-action 摘要（画布是 run 级导航，Home 是项目级）。
- 现有 `.workflow-pipeline__*` 类与契约测试保留（回退路径 + L0 复用）。

## 6. 实施阶段

- **P1 画布视图**：引入选型依赖（拍板 A/B），Work 页管线条 → 画布（L0+L1），平移/缩放/
  适应视图/键盘基础，管线条作为回退。契约测试：回退渲染、L0 节点结构、缩放状态切换。
- **P2 门卡细节**：L2 细节卡（推荐/证据/决策动作），批准路径 ≤2 次交互验证；
  决策动作复用 Review API，审计元数据一致（`decision_origin=web`）。
- **P3（未来）**：并行分支/泳道渲染、跨项目 run 画布、小地图；与 D3 后端拓扑联动。

## 7. 验收标准

1. L0↔L1↔L2 缩放吸附正确；双击聚焦、适应视图回 L0。
2. 从 L0 到批准一次 gate ≤2 次交互（活体实测）；走查 3.0 复测 5 任务不劣于走查 2.0。
3. 键盘全流程可用（方向/Enter/Esc/缩放/适应）；回退路径（管线条）功能完整。
4. 细节卡展示的推荐/证据与 Review 页同源一致；决策写入审计元数据完整。
5. 无新后端字段；en/zh-CN 键齐全。
6. 并行拓扑数据出现时按泳道渲染，未出现时顺序渲染（P3）。

## 8. 验证（Tier 2/4 + 活体）

- 契约测试：回退路径、L0 结构、缩放层切换、细节卡动作（mock API）。
- `npm run lint/test:unit/build`；活体：隔离 workspace + fake worker，走查 3.0
  （5 任务 + 批准路径步骤数 + 键盘路径 + 回退路径），零 console 错误。

## 9. 非目标（本轮明确不做）

- 不做拖拽编辑/拓扑修改（画布是视图不是编辑器）。
- 不把 Review/Knowledge 内容搬进画布（画布是导航/引导层，详情留在原页面）。
- 不做后端改动。
- 不用画布替代"项目管理"缺口（项目总览、Settings JSON 结构化、列表搜索——独立小项，
  见 §10）。

## 10. 并行小项（管理便利性，独立于画布）

画布解决可视化密度；以下"管理不便"缺口按小 PR 独立推进，不与画布耦合：
1. **Home 项目总览**：ready 后 Home 显示 run 当前阶段 + 下一 gate + blockers +
   交付摘要 + 各空间快捷入口（后端 home payload 需加 `workflow_steps`，唯一后端配合点）。
2. **Settings 剩余 JSON 结构化**：integrations/delivery/diagnostics 三区（C3 只做了 workers）。
3. **项目列表搜索/最近使用**（ProjectsPage 现仅 5 分组）。

## 11. 选型结论（2026-08-15 已拍板并落地）

1. 技术选型：**A（React Flow @xyflow/react 12.x）**。
2. 细节卡形态：**画布内浮层**（右侧覆盖卡，Esc 关闭）。
3. 决策动作：**抽取共享 `DecisionActions`/`EvidenceSummary`**，Review 页与画布共用。
4. 移动端：**保持管线条回退**（`prefers-reduced-motion` 或窄屏走回退路径），不做触屏画布。
