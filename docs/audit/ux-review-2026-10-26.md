# GoodTeam UX 评估与改进 · 2026-10-26

范围：Projects、Work、Team、Review、Knowledge、Settings 的共享界面，以及项目查找与进入流程。
方法：使用 `ui-ux-pro-max` 设计检索、`frontend-design` 视觉决策和最新 [Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md) 审核；代码检查与隔离工作区浏览器实测结合。没有操作真实项目或调用真实 Worker。

## 评估结论

现有产品已经有清晰的项目分区、审批边界、键盘焦点、深浅色和移动端触控尺寸支持。本次最值得修复的是共享样式的可读性与层级、项目列表的导航语义和状态连续性。沿用当前产品结构，以小范围修改覆盖主要页面。

### 设计方向

- 颜色：画布 `#f5f5f6`、内容 `#ffffff`、正文 `#242429`、辅助文字 `#6c6c75`、强调 `#424fc5`、选中背景 `#efeffb`；深色使用现有对应 token。
- 字体：保留已经本地打包的 Geist / Geist Mono，不增加字体下载；共享辅助文字 12px、控件 14px、页面说明 15px，使用 rem 随浏览器文字设置缩放。文档继续采用现有独立阅读排版。
- 布局：左侧项目导航 → 当前页面与任务内容 → 证据/上下文；保持内容左对齐。手机将项目导航改成图标在上、标签在下，四个入口同列对齐。
- 视觉重点：用紫蓝色边线、背景与字重共同标识当前位置；操作按钮使用较紧凑的圆角矩形，状态标签保留胶囊形，区分动作与状态。
- 设计检索返回的落地页结构与工作台不匹配，未采用。只借鉴与企业工作台匹配的功能优先、清晰层级、低干扰交互建议。

## 验证边界与后续观察

这是针对已观察问题的共享 UX 改进，不代表覆盖所有状态的完整无障碍认证。浏览器回归使用真实 HTTP 与隔离假 Worker 工作区；不涵盖真实模型输出、外部交付或全部历史数据组合。

Work 在较矮的桌面窗口中，上方的任务、Git、历史和 Goal 信息会占用较多垂直空间，输入框可能需要滚动才能到达。后续可围绕日常任务频率做一次单独的信息优先级调整；本次未隐藏已有功能或重排工作流。Review/Knowledge 的无数据提示仍可进一步提供更直接的下一步入口。
